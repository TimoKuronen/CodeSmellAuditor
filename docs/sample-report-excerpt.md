# Sample Report Format

This excerpt shows the report structure generated by CodeSmellAuditor.

## File naming

```
{TargetFileNameWithoutExtension}_{yyyyMMdd_HHmmss}_Critique.md
{TargetFileNameWithoutExtension}_{yyyyMMdd_HHmmss}_Critique.summary.json
```

Example: `SampleService_20260707_120000_Critique.md`

System audits use a combined name: `SystemAudit_{yyyyMMdd_HHmmss}_Critique.md`.

## Front matter

```yaml
---
TargetFile: SampleService.cs
AuditDate: 2026-07-07 12:00:00
Tags: [code-smell-audit]
---
```

## Body (compact format)

```markdown
# Audit Report: SampleService.cs

Status: REVIEW REQUIRED
Score: 72

## Top Findings
- [F1] Line: 14 | Rule: 00-engineering-standard.mdc | Fix: judgment
  Evidence: `public SampleService(IClock clock, ILogger log, IStore store, IQueue queue, ...)`
  Issue: Constructor takes 8 dependencies; group related configuration.
- [F2] Line: 40 | Rule: 10-csharp-style.mdc | Fix: mechanical
  Evidence: `private int retrycount;`
  Issue: Field name does not follow the camelCase convention.

## Missing Context
- Composition root registration not visible in this file

## Recommended Next Step
Group the queue and store settings into one options object.

## Grounding

Model status: REVIEW REQUIRED | Final status: REVIEW REQUIRED | Grounded: 1 | Ungrounded: 1

- F1 grounded - SampleService.cs:12 (reported line 14, found at 12)
- F2 ungrounded - evidence not found in SampleService.cs
```

Everything above `## Grounding` is model output. The tool appends `## Grounding` after checking each Evidence quote against the audited source: whitespace differences are ignored, `...` marks a gap within one line, and very short quotes are rejected. With a findings section, the final status is review required only when at least one finding is grounded; ungrounded findings never fail a run. Without a findings section, the model `Status:` line decides, and a missing or invalid Status fails closed.

Tool failures (Ollama down, empty response, budget exceeded) use exit `2`, print the cause, and do not write a critique file. `Score:` is a rough qualitative signal for that run only - not a regression metric.

## Summary sidecar

```json
{
  "contractVersion": 1,
  "target": "SampleService.cs",
  "report": "SampleService_20260707_120000_Critique.md",
  "modelStatus": "REVIEW REQUIRED",
  "status": "REVIEW REQUIRED",
  "findingsSectionFound": true,
  "findingsTruncated": false,
  "grounded": 1,
  "ungrounded": 1,
  "findings": [
    {
      "id": "F1",
      "file": "SampleService.cs",
      "line": 12,
      "rule": "00-engineering-standard.mdc",
      "fix": "judgment",
      "grounded": true,
      "issue": "Constructor takes 8 dependencies; group related configuration.",
      "evidence": "public SampleService(IClock clock, ILogger log, IStore store, IQueue queue, ...)",
      "note": "reported line 14, found at 12"
    }
  ],
  "usage": {
    "promptTokens": 3283,
    "outputTokens": 459,
    "promptChars": 14482,
    "numCtx": 8192,
    "charsPerToken": 4.41,
    "contextHeadroomTokens": 4450
  }
}
```

The second finding is omitted here for brevity; the sidecar lists every finding, grounded or not. `usage` carries the token counts Ollama reports for the call and is absent when Ollama does not report them.

## Interrupted reports

If the model reaches its output limit before the findings end, the report is kept with the findings it has, `findingsTruncated` is `true`, and the final status is review required. A cut in a later section does not affect the status.
